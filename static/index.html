How it works

  1. Create a minimally-scoped Crowdin token

    Granular Access, scoped to one project, with only the handful of permissions badges actually need — see the setup guide for the exact list.

  2. Paste it once — we encrypt it immediately

    Encrypted at rest before the row ever hits disk. See below for exactly how.

  3. Copy two image links into your README

    They stay live — no rebuild, no CI step, no manual refresh.

How your token is protected

A short, honest summary — the full technical detail is one click away.

  • Your token is encrypted before it's stored — never written to disk in plain text.
  • The encryption key lives only in the server's runtime environment — never in the database, a backup, or a log.
  • A copy of the database alone can't recover your token.

Customize the contributor grid

These are all just query string values on the URL — no re-onboarding required to change them.

/embed/{public_id}/contributors.svg?limit=10&unit=words&hideOwner=true
  • limit — how many contributors to show, 1–100 (default 30)
  • unit — rank by words, strings, or characters (default words)
  • hideOwner — set to true to exclude the project owner from the grid (default false)

FAQ

How do I revoke access?

Delete the Personal Access Token in your Crowdin account — this is the real kill switch and takes effect immediately, before the service's cache even expires. To also remove your project's row from our database, email revoke@crowdin-stats.rewake.org with your badge URL. We manually confirm and delete within a few days — no automated self-service delete exists yet, and this page says so plainly rather than implying one does.

What can the token you're storing actually do?

If you follow the Granular Access + single-project setup instructed during onboarding — Projects and Translation status set to Read only, Reports set to Read and Write (Crowdin requires Write to generate a report, even though generating one only reads translation activity and changes nothing in your project) — a worst-case compromise of our database (ciphertext only) or of a live decrypted token in transit is limited to reading translation progress and contributor activity for that one project. It cannot modify translations, invite members, or access any other project. This is your responsibility to configure correctly; nothing on Crowdin's side enforces it if you paste a broader-scoped token instead.

What happens if I delete my Crowdin token but forget to email you?

The badge endpoints will start failing (Crowdin returns 401) on the next cache refresh; the last successfully cached SVG keeps being served stale until it errors out, at which point the image simply stops updating. The row stays in the database, encrypted and unusable, until a revoke email is sent — a manual-cleanup limitation, not a hidden auto-expiry.

Can you read my Crowdin data?

Only what your scoped token permits — translation progress and top-members reports on the one project you registered. The Crowdin Project ID itself (not the token) is stored unencrypted, since it isn't a credential — relevant mainly if your project is private. See SECURITY.md for the precise statement.

Is this affiliated with Crowdin?

No — independent, unofficial, built against Crowdin's public API using their official Go client.

What if I change my mind about a limit or unit value?

Just edit the query string in the README — no need to re-onboard, the public_id doesn't change.

Where's the source code?

Right here on GitHub — for a tool asking for API tokens, being able to read exactly what it does is a stronger trust signal than any explanation on this page.
